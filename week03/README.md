# Week 03 실습: 셸 스크립팅과 자동화 기초

## 1. 실습 내용 요약
- 반복 작업을 셸 스크립트(`.sh`)로 묶어서 실행하는 자동화 실습
- Shebang(`#!/bin/bash`) 선언과 실행 권한(`chmod u+x`) 부여
- 스크립트 실행 위치에 상관없이 동작하게 만드는 `cd "$(dirname "$0")"` 관용구
- 환경변수와 `if` 조건문으로 실행 전 환경 점검하기

---

## 2. 셸 스크립트 기본 문법 정리

### (1) 자동화가 필요한 이유
- 매일 로그 파일에서 에러 줄을 찾고 백업 폴더로 옮기는 데 10분이 걸린다면, 1년이면 약 60시간이 낭비됨.
- 스크립트로 짜두면 명령어 한 번에 몇 초 만에 처리할 수 있음.

### (2) Shebang과 실행 권한
- `#!/bin/bash`: 이 스크립트를 어떤 셸(bash)로 읽을지 첫 줄에 적어둠.
- 실행할 때 `Permission denied` 에러가 나면 권한을 줘야 함:
  ```bash
  chmod u+x start.sh
  ./start.sh
  ```
- 환경변수 `PATH`에 등록된 폴더가 아니면 그냥 `start.sh`로 실행되지 않으므로 앞에 `./`를 붙여야 함.

### (3) 경로 고정 관용구
터미널에서 어느 디렉터리에 있든 스크립트 파일이 있는 위치를 기준으로 실행되도록 맨 위에 아래 코드를 작성함.
```bash
cd "$(dirname "$0")"
```

---

## 3. 조건문으로 환경 점검하기
스크립트 실행에 필요한 환경변수가 빠졌는지 체크하는 코드 작성.

```bash
#!/bin/bash
cd "$(dirname "$0")"

# 환경변수가 비어있는지 확인 (-z)
if [ -z "$MODEL_NAME" ]; then
    echo "MODEL_NAME 설정이 없어서 기본값 qwen:0.5b 로 설정합니다."
    export MODEL_NAME="qwen:0.5b"
fi

# 명령어(ollama)가 설치되어 있는지 확인
if ! command -v ollama &> /dev/null; then
    echo "ollama가 설치되어 있지 않습니다."
    exit 1
fi

echo "실행 준비 완료: $MODEL_NAME"
```

## 4. 정리
- 리눅스 서버 운영할 때 반복 작업이나 배포 명령어를 셸 스크립트로 자동화하는 게 왜 중요한지 체감함.
- 스크립트 짤 때 권한 설정(`chmod u+x`)이랑 기준 경로 설정(`dirname "$0"`)은 기본으로 챙겨야 함.
